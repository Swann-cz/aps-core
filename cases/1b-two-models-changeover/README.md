# 1b 两车型、一个月、一次换型

规格出处：`spec/CORE_MODEL.md` §8 1b；C4、C15 镜像、§5 换型（rev 139，2026-10-24 裁决：换型按补线处理；上游供不上时下游不满产合法）；C16 顺接换型与跨车型先进先出（rev 169，2026-10-25 裁决）。本目录由 Claude 维护，`build.py` 重新生成全部文件。

## 设定

- 计划期 2026-03-02（周一）至 03-31（周二），30 个自然日，22 个工作日；周末 `is_working_capable=false`。无周六、加班授权，无停线。
- 车型 A 绑 BS1（10 JPH，80 台/天），胶龄 14；车型 B 绑 BS2（8 JPH，64 台/天），胶龄 30。PS、AS_MAIN、AS_FIN 10 JPH，80 台/天。单班焊装：同一天只能开一条线（C4）。
- 目标：BS1、BS2 各 69，WBS 37，PS 147，PBS 80，AS_MAIN 100，AS_FIN 40；物理上限 WBS 69、PBS 150；`wbs_hi = null`。
- 期初：BS1 有 A 69；BS2 为 0；WBS 37 A、PS 147 A、PBS 60 A + 20 B、AS_MAIN 100 A、AS_FIN 40 A；成品 0。B 在 PBS 有在制，不属于“首次启动”。
- 需求：PR(A) = 1333，PR(B) = 187（都在 2026-03）。WS：A 在 03-31 交 1333；B 在 03-31 交 187。
  - rev 169 改：原来 B 在 03-20 交 100。按 C16，B 的车要排在全链约 400 台 A 后面，只换一次型时 B 最早 03-27 才下线，03-20 交不出 100 台，最优解会变成两次换型。为了保留“一次换型”这个算例的用途，B 的交期改为月底一次交齐。

## 手算：为什么最优解唯一

记第 k 个工作日为 k（03-02 是 1，03-17 是 12，03-31 是 22）；c 为 BS1 的清线日（换型首日）。

1. **换型的形状是定的。**
   - c 日：BS1 投入 0，产出全部 69 台；当天 BS2 不能开（C4）。
   - c+1 日：BS2 投入 64 台。日末 64 台，没到 69，不得向下游供车；WBS 也已在目标，PS 拿不到车，下游全部为 0。
   - c+2 日：BS2 再投入 64 台，128 − 69 = 59 台可以当天送出，全链流量 59；日末所有节点回到目标，换型结束。
   - 之后 BS2 每天满产 64；WBS 一直在目标，PS 和总装只能做 64（C15 镜像，合法）。
2. **c ≥ 12。** A 的车只能来自期初的 453 台（69 + 37 + 147 + 60 + 100 + 40）加 BS1 的投入。PR(A) = 1333，所以 BS1 至少要投 880 台，即 11 个工作日满产 80；清线日不投入，所以清线最早在第 12 个工作日。
3. **c ≤ 12。** B 的 167 台（187 − PBS 期初的 20 台）只能来自 BS2，并且按 C16 要排在全链 A 后面。换型开始时全链（WBS 37、PS 147、PBS 80、AS_MAIN 100、AS_FIN 40，都在目标）共 404 台 A，B 下线之前这 404 台必须先被推出完成线。换型期和换型后，节点日末低于目标不得供车，所以全链每天只能前进“BS2 送来的量”：c+2 日 59 台，之后每天 64 台。到 03-31（第 22 个工作日）累计推出 59 + 64 × (20 − c) 台，要 ≥ 404 + 167 = 571，得 c ≤ 12。
   所以 c = 12，即 03-17 清线、03-18 开 BS2、03-19 换型结束。
4. **每天都必须满产。** c = 12 时焊装投入合计 80 × 11 + 64 × 10 = 1520，正好等于 PR(A) + PR(B)。月末是正常日，各节点不得低于目标，所以 FOK 合计不超过焊装投入。要做到 L1a = 0，焊装每天都必须满投。
5. **下游流量也唯一。** L5 = 0 要求正常日每个节点都恰好在目标。换型期内，"日末未达目标不得供车"和"不能高于目标"两条同时卡住，每个车间当天流量只能等于上游送来的量。
6. **目标值：** L2 = 1（一次换型，旧线清线不另计），其余各级为 0。

| 日期 | 焊装 IN / OUT | PS = AS_MAIN = AS_FIN 流量 | 节点 EOD（合计） | 阶段 |
| --- | --- | --- | --- | --- |
| 03-02 至 03-16 的工作日（11 天） | BS1 80 / 80 | 80 | 全部等于目标，BS2 为 0 | NORMAL |
| 03-17 | BS1 0 / 69 | 69 | BS1 0，其余等于目标 | CHANGEOVER |
| 03-18 | BS2 64 / 0 | 0 | BS2 64，其余等于目标 | CHANGEOVER |
| 03-19 | BS2 64 / 59 | 59 | BS2 69，全部等于目标 | CHANGEOVER（当天结束） |
| 03-20 至 03-31 的工作日（8 天） | BS2 64 / 64 | 64 | 全部等于目标，BS1 为 0 | NORMAL |
| 周末 | 0 | 0 | 不变 | NORMAL |

FOK 合计：80 × 11 + 69 + 0 + 59 + 64 × 8 = 1520 = 1333 + 187。

## 车型拆分（C16）

计划期内焊出的车按焊出顺序走：A 全在 B 前面。期初在制排在最前，期初车之间（含 PBS 期初的 B 20 台和期初 A）不分先后，所以同一天的车型拆分不唯一。生成器只按车间和节点**合计**比对（`expected.engine.compare = "aggregate"`），另外核对两个车型的全期 FOK 分别等于 1333 和 187。

`build.py` 按先进先出队列生成逐车型计划（`_reference-plan.json`），PBS 期初的 B 20 台排在队首：03-02 随第一批出 PBS，03-04 下线进成品库存。计划期内焊出的 B 在 03-27 首次下线（39 台），03-30、03-31 各 64 台，月底累计 187 台；A 在 03-27 交满 1333 台。月末全链都是 B。判定器应判这份计划为 ACCEPT，可以拿来抽查。

## 反例

- `counter/wbs-hold-32.plan.json`：03-17 PS 只吃 37 台，WBS 留 69 台（等于物理上限，高出目标 32 台）；03-18 再送出 32 台。rev 182 起换型补满期也要满产：WBS 有车、PBS 未满，PS 只吃 37 违反 C14。判定器应 REJECT，违规条款只有 C14（rev 182 前它是合法但 L5 更差的解）。
- `counter/refill-early-supply.plan.json`：03-18 BS2 还没补满，WBS 就把 37 台全部送进 PS，日末 WBS 为 0，低于目标仍在供车；03-19 再补回。违反换型的逐级补满（`CHANGEOVER`）；当天 PS 只进 37，WBS 日末 0 不等于目标，不算 C15 上游受限，同时记 `C14`。判定器应 REJECT，违规条款为 C14、CHANGEOVER。它同时带来 B 欠交（L1b > 0），但欠交只计入目标，不算硬错误。
